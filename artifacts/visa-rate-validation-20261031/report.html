What was tested

Two approximately 35-second runs at each requested rate, using the connected 53230A on channel 3. Tests used the real OpenUFC acquisition worker, normal million-reading segments and one-second nominal read batches, background disk recording, live and final Allan-deviation calculation, and frontend event JSON serialization. The instrument display remained in its existing state. Driver newline detection was confirmed disabled by reading the VISA attribute.

Delivered rate is all received readings divided by the interval from the first INIT return to the stop/drain request. It includes restart downtime; small command/timing uncertainty remains. Gate readback is the requested instrument setting, not a measurement of physical sample spacing. The source signal was live and not independently stabilized.

Integrity checks

Received arrays and saved file payloads were compared by SHA-256. Every saved reading was checked for finite, positive, non-sentinel values. Stop/drain completion, zero remaining readings, instrument error queues and questionable-event status were checked. Full restart segments are marked in each .lmp file.

Limits

Passing data integrity does not establish a stable delivery cadence. The 100 kHz and 500 kHz settings showed read stalls of up to 11 and 22 seconds, respectively. The second 500 kHz run also had a read timeout: some acquired readings may have been lost even though all successfully received arrays were saved correctly. These are short-duration USB tests, not a long-term stability or measurement accuracy certification. GUI rendering and LAN hardware were not included in these timing runs. Separate Electron smoke tests exercise all rate choices and a 500,000-reading display batch. Waveform, PSD and ADEV time scales still use the nominal selected rate; the 100 kHz and 500 kHz presets must not be treated as verified timing. The Keysight datasheet specifies a 10 µs minimum continuous gate and up to 75,000 frequency readings/s.
